# Spec

Revamped the AI layer into a Meterless-style threat council with Zetaris intel.

- `zetaris_client.py` — Zetaris REST adapter (`POST /sql-editor/sqls/run-query`) for read-only Lightning SQL. Uses `ZETARIS_*` env vars. Falls back locally when unset.
- `meterless_memory.py` — H-MEM–style `MemoryStore` / `MemoryRetrieval` for council arguments and findings.
- `meterless_scout.py` — Scout–style intent router. Its default plan still starts from the preloaded arsenal (`policy` is `arsenal_first_open_methods`). Availability prompts route to `ddos`, `rate_limit`, `load_balancing`, and `denial_of_service`. Auth prompts can also select `user_enumeration`, `oauth`, `jwt`, `session_fixation`, and `security_logging`. Injection prompts can also select path traversal, XXE, SSTI, deserialization, and prototype pollution. Platform prompts route to `cors`, `tls_posture`, `graphql`, `sensitive_data`, and `cloud_config`.
- `council.py` — Parallel agent council (recon, attacker_mindset, defender, intel, upload_forms). Defender can vote for `user_enumeration`. Intel can vote for `ddos`, `rate_limit`, and `load_balancing`. Agents still run in parallel, and their proposals are applied in roster order so tied votes stay stable. When a model key is set, each agent writes its argument and tool votes through `model_client` and may name inspection methods outside the repo. Otherwise it uses the local template and the starting set. Wired to `DebateManager` for guideline prompts, collision resolution, and per-agent storage. Overlooked fills stay on the starting set, including the four availability and enumeration checks.
- `debate_manger.py` — Debate manager: loads `guidlines/`, rejects bare agree/disagree, resolves duplicate parallel tool votes, fills overlooked starting-set checks, and keeps an extra method when agents voted for it. Stores context in `local_debate_storage/`, and ships a sample round under `sample_conservations/`.
- `tool.py` — Preloaded cyber-tool arsenal used as the convenient starting set, including user enumeration, DDoS hardening, rate limit, and load balancing checks. Other snake_case inspection methods are accepted and review the fetched response or uploaded source. When `stay_inspect` is set on the target, those extra methods are skipped. Command-shaped names are rejected. When a model key is set, an extra method can ask that model to review the collected excerpt.
- `cve_manger.py` — Matches CVEs only when an exact package version falls in the affected range. Queries OSV by ecosystem, name, and version, and badges a hit that is also in CISA KEV. Name overlap is not a match. Does not download or run exploits.
- `manifests.py` — Reads exact versions from `requirements.txt`, `package.json`, `package-lock.json`, and `go.mod`.
- `model_client.py` — OpenAI-compatible council client. Calls the model only when `METERLESS_API_KEY` is set. Snake_case votes outside the starting set are kept. Command-shaped votes are dropped.
- `cve_knowledge.py` — On initialization, seeds `cve_knowledge/common_cves.json` and `cve_knowledge/zero_days/<cve_name>.json` with name, how it works, and defend_against. Used as agent context and after-action defenses.
- `main.py` — Prepares URL/source targets, reads exact package versions, runs the council, matches CVEs by affected version, and returns a scored report with narrative and after-action steps. The single GET also records TLS protocol and certificate expiry when the socket exposes them. Uploaded archives include Dockerfile names plus Terraform and YAML suffixes. `stay_inspect` is off unless the caller passes it in. `run_scan` calls `safety.gate_before_agents` before any fetch or council work. A URL scan needs a passed site proof. A labeled source owner that does not match is refused. Unlabeled source is assumed to be the caller's.
- `summary.json` — Multi-source CVE summary cache.
